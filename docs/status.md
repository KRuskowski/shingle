## Readiness

The `shingle` binary runs nested inside an existing Wayland or X11 session, or headless, and is useful for isolated testing. It is **not** yet a drop-in hardware replacement for Wayfire. The largest gaps are:

- Not run on hardware yet: the native backend takes the seat with libseat, reads input with libinput (NB-6) and drives its monitors with atomic KMS and copy scanout (NB-7) or zero-copy scanout into GBM buffers (NB-8), following DRM hotplug and Wayfire's mode configuration (NB-9), one CRTC per monitor (MO-7), with a hardware cursor, VRR, async flips and render fences (NB-10), but none of it has run on a seat or a GPU yet ([native-testing.md](native-testing.md)). Useful sessions need the nested backend.
- Clients can present DMA-BUFs through `zwp_linux_dmabuf_v1` with implicit sync (DB-4) or explicit sync through `linux-drm-syncobj-v1` (DB-5), and shared-memory buffers go to the GPU straight from the client's pool (DB-6); direct scanout of client buffers (DB-7) is not built, and zero-copy scanout of Shingle's own frames (NB-8) is built but not run on a card. The design is [design/dmabuf.md](design/dmabuf.md). NVIDIA's EGL clients have not been seen on DMA-BUF or syncobj: the GPU namespace hides the card node, without which NVIDIA's EGL cannot start its Wayland platform.
- XWayland runs X11 applications as Shingle windows, with X focus, menus and tooltips, client state requests and a shared clipboard and primary selection (XW-2 to XW-5), but there is no drag and drop between X and Wayland yet (XW-6).
- Multi-output support is incomplete: the window model, sessions and configuration handle several outputs and workspace sets (MO-1) the compositor keeps several outputs with their globals, layout and unplug policies (MO-2) client protocols are per output (MO-3), focus and windows move between outputs (MO-4), the frontend draws a scene per output (MO-5), nested opens a window per output (MO-6) and native lights one CRTC per monitor (MO-7); headless, offscreen and nested run with several outputs, native only through the fake card so far ([design/multi-output.md](design/multi-output.md)).
- Several Wayfire plugins and visual effects are missing, including wrot's 3D mode. The survey of every Wayfire plugin, option, protocol and IPC method is [design/wayfire-gaps.md](design/wayfire-gaps.md) (2026-11-26, by reading the code, nothing run). It found that a WCM-written `wayfire.ini` did not load; since WG-1 it does, with a warning for each value Shingle cannot use, since WG-2 it gets Wayfire's defaults and plugin list, since WG-3 children get Wayfire's variables, since WG-4 wf-shell's `zwf_shell_manager_v2` is there, since WG-5 touchpad swipes move between workspaces, since WG-6 windows get Wayfire's server-side frame and since WG-7 Alt+Tab shows Wayfire's switcher thumbnails. All seven planned steps are done; the survey's [Later](design/wayfire-gaps.md#later) list remains.

Do not claim that Shingle is more stable or uses fewer resources than Wayfire. No comparative benchmark or long-running soak test has been done, and nested wgpu rendering, CPU buffer copies and per-frame work may make it slower in some scenarios.

## Implemented

### Compositor and renderer

- wgpu rendering with a winit nested frontend. `shingle-render` itself has no winit dependency: a shared `GpuContext`, a per-output `RenderState`, one `draw` pass, and `WindowTarget` and `OffscreenTarget`, with `Renderer` and `OffscreenRenderer` as thin wrappers (native backend NB-1). The wgpu `drm` feature is no longer enabled.
- Configured colours ([Colour and focus fixes as built](design/wayfire-gaps.md#colour-and-focus-fixes-as-built)): a configured colour names the bytes Wayfire's GLES2 renderer writes, so crates/shingle-render/src/color.rs decodes it from sRGB, `srgb_fill` (premultiplied) for solid tiles and `srgb_clear` for the clear colour, and the scene uses them for every colour option drawn as a tile or clear colour; colours rasterized on the CPU into sRGB textures already showed their bytes. The shader's gamma LUT is indexed by each tile's sRGB byte and decoded again, so with the identity ramp every byte reaches the target unchanged. Translucent colours still blend in linear light, and inversion and dimming still work on linear values, where Wayfire works on bytes.
- DMA-BUF import in the renderer (DB-1 in [design/dmabuf.md](design/dmabuf.md#db-1-as-built)): with `GpuOptions::dmabuf`, which nested and native set, the device is opened through wgpu-hal with `VULKAN_EXTERNAL_MEMORY_DMA_BUF`, `VK_EXT_queue_family_foreign` and `VK_KHR_external_semaphore_fd`; `GpuContext::dmabuf()` lists the render node and the single-plane modifiers of ARGB, XRGB, ABGR and XBGR8888 that can be imported and sampled or rendered to; `GpuContext::import_dmabuf` imports a buffer for sampling or rendering; and `draw` moves imported images in from and out to the foreign queue family around each frame. Tiles of X formats ignore alpha, and UNORM-only modifiers are decoded from sRGB in the shader. Nested and native log `DMA-BUF import available: render node 226:128, 28 format and modifier pairs` or why it is unavailable. Nothing imports client buffers yet; `zwp_linux_dmabuf_v1` is DB-4.
- Buffer lifetime (DB-3 in [design/dmabuf.md](design/dmabuf.md#db-3-as-built)): every attached buffer is locked from `wl_surface.attach` until its commit applies, through synchronized-subsurface caches and the commit queue; the locks of one `wl_buffer` share a count, and the last one to drop queues `wl_buffer.release`, sent at the end of the compositor's turn. A buffer replaced before it was shown, or held by a destroyed surface, is therefore released; before DB-3 it never was. Single-pixel buffers are copied and released when their commit applies; shm buffers too where nothing uploads them (headless), and otherwise after their upload (DB-6, below). Commits pass a per-surface commit queue first, which holds a blocked commit and every later one of its surface until the first is ready and applies them in order, unmerged. Its blockers are FIFO barriers and commit-timing deadlines, each update with its own as in wlroots (since DB-4; they used to be merged, which froze NVIDIA's Vulkan clients), and DB-4's implicit-sync wait. Deferred and cached commits no longer discard what the client attached after them. `BufferSnapshot` has `content` (`SnapshotContent::Pixels`) and `rgba()` instead of the `rgba` field.
- Client DMA-BUFs (DB-4 in [design/dmabuf.md](design/dmabuf.md#db-4-as-built)): `zwp_linux_dmabuf_v1` version 5, offered once a frontend's renderer can import and names a render node (`Frontend::enable_dmabuf`, logged as `linux-dmabuf version 5 on render node 226:128, 28 format and modifier pairs` or why not; `SHINGLE_DMABUF=0` turns it off), with one feedback tranche on the render node and a sealed format table that every client gets as its own read-only descriptor. `create` and `create_immed` check the params as the protocol and wlroots do (every params error, `failed` for y-invert, interlaced and oversized buffers) and then really import the buffer, so `failed` (or `invalid_wl_buffer` for `create_immed`) means the renderer cannot sample it. The frontend caches imported textures by buffer serial, so each buffer is imported once and later commits only pick its texture; textures go when the buffer does and are imported again from the kept fds after a filter change or a GPU loss. A DMA-BUF is not copied: the surface's snapshot holds it locked, and every frame that samples it keeps a lock until the GPU has finished, so `release` follows the GPU. A commit whose buffer does not poll readable waits in the commit queue until its implicit write fences signal. Clients start only after the renderer exists (`Frontend::start_clients`), so they find the global when they first look. `SHINGLE_TRACE_BUFFERS=1` logs each buffer's path.
- Explicit sync (DB-5 in [design/dmabuf.md](design/dmabuf.md#db-5-as-built)): `wp_linux_drm_syncobj_manager_v1` version 1, which Wayfire does not have, offered with linux-dmabuf when the render node has timeline syncobjs and `DRM_IOCTL_SYNCOBJ_EVENTFD` (logged as `linux-drm-syncobj version 1 on render node 226:128` or why not; `SHINGLE_SYNCOBJ=0` turns it off). The compositor opens the render node itself, never a card node. Commits follow wlroots' rules, with every protocol error; a commit whose acquire point has not signalled waits in the commit queue on an eventfd instead of the implicit fences, so only its surface stops; release points are signalled with `wl_buffer.release`, when the buffer's last lock drops after the GPU has finished with it.
- Shared-memory buffers without CPU copies (DB-6 in [design/dmabuf.md](design/dmabuf.md#db-6-as-built)): with `Frontend::attach_gpu`, which nested, offscreen and native call once their renderer exists, a `wl_shm` commit's snapshot holds the client's buffer (`SnapshotContent::Shm`) instead of an RGBA copy, and the frontend uploads it in `Frontend::process`, right after the dispatch that committed it, drawn or not: with `Queue::write_texture` from the client's pool, with its stride, into a texture of its own byte order (`Bgra8UnormSrgb` for ARGB and XRGB, `Rgba8UnormSrgb` for ABGR and XBGR, X formats through the opaque tile flag), only the damaged rectangles into a texture that fits. The buffer goes back in the same turn, before any frame. Pools sealed against shrinking stay mapped; others are checked with `fstat` and mapped per read. Uploaded textures are kept while their surface is mapped, rebound on a filter change and copied on the GPU for a geometry crossfade. The CPU-only headless backend still copies shm buffers at commit. `SHINGLE_TRACE_BUFFERS=1` logs `shm upload N bytes` with the bytes copied from the pool.
- XDG toplevels and popups, layer shell, dialogs, decorations, subsurfaces, viewports, fractional scaling and shared-memory buffers.
- Tiling, floating windows, exact floating geometry, snapping, focus, stacking, minimize, fullscreen, sticky and show-desktop.
- Workspace navigation: directional, last, numbered, carry and send actions, with configurable wraparound.
- Scale and Expo overviews, vswitch transitions, zoom, inversion, opacity, window rotation, and opening/closing animations.
- Screencopy captures the frame as drawn when a frontend renders (nested, native, offscreen; DB-2 in [design/dmabuf.md](design/dmabuf.md#db-2-as-built)), with inversion, Scale, Expo and animations, as Wayfire's does: `Compositor::set_frame_capture` makes `copy` emit `Event::CaptureRequested`, the frontend draws its next frame once more offscreen at the output's logical size and answers with `Compositor::finish_capture`, which writes the shm buffer and sends `ready`, or `failed`. Headless keeps the CPU composite of client pixels.
- Screencopy, gamma, tearing control, FIFO, commit timing, presentation timing and pointer warp. A client may destroy its FIFO or commit-timer object and create a new one for the same surface, as Mesa's Vulkan WSI does on swapchain recreation; before NB-3 that was a protocol error that disconnected every Mesa Vulkan client on its first resize.

When an X client copies, its `TARGETS` become an X11 source (`SourceOrigin::X11`, keyed by `SourceKey::X11`) that focused Wayland clients and wlr-data-control clients are offered like any other, and a read converts the target into a transfer window of its own and copies the property, or the `INCR` chunks, into the reader's descriptor. When a Wayland client copies, the window manager takes the X selection, answers `TARGETS` and `TIMESTAMP`, and passes data requests to the Wayland source through a pipe, writing the result whole up to 64 KiB and through `INCR` in 64 KiB chunks above. UTF-8 text is `UTF8_STRING`, plain text `TEXT` and `STRING`, and other types keep their names. Every transfer descriptor is non-blocking and pumped each turn, with a calloop source on a duplicate of each that can move, so a slow writer or reader stalls only its own transfer. `disable_primary_selection` leaves `PRIMARY` unbridged. A new wlr-data-control device is now told both selections at once, as the protocol requires, which `wl-copy --primary` needs.

### The `shingle` binary

One binary, `shingle` (package `shingle-bin`, crates/shingle-bin), replaces `shingle-nested` and the old headless-only `shingle`; `shingle-nested` is now a library and its binary is gone. It picks its backend the way Wayfire (through wlroots' `wlr_backend_autocreate`) does: `--backend nested|native|headless` or `--headless` first, then `SHINGLE_BACKEND`, then nested when `WAYLAND_DISPLAY`, `WAYLAND_SOCKET` or `DISPLAY` is set (empty values count as unset), and native otherwise. Native refuses an SSH login without `XDG_SEAT` before anything is opened, with "no seat", the reason native was selected and status 1; see [Native backend](#native-backend-seat-and-input). Unknown backends, unknown or repeated options and conflicting backends exit with status 2 and point to `--help`. The options are the union of the old binaries' (`--config`, `--ipc`, `--spawn`, `--headless`) plus `--backend`, `--help` and `--version`; headless now accepts `--ipc` and `--spawn` too. `WAYFIRE_SOCKET` is exported before any client starts, so restored and autostarted clients and `--spawn` children see it, which they did not in nested before. Headless registers a keyboard, a pointer and a touch device for STIPC input, as Wayfire's stipc plugin does on any backend, and reports a frame at the output's refresh rate, as wlroots' headless backend does, so clients that wait for frame callbacks, such as a nested Shingle, keep drawing (XW-4). `--backend offscreen` (DB-2) is headless with the frontend: it draws with the GPU (wgpu's high-performance adapter, opened for DMA-BUF import before the socket exists) into an offscreen target at the output's physical size, on request and at most once per refresh interval, reports a frame as presented once the GPU has finished it, with a frame counter, and serves screencopy from the drawn frames; input comes from STIPC only. It is never selected automatically, and it is what the GPU harness runs clients in. The binary blocks SIGINT and SIGTERM before any backend starts, so threads that a GPU driver starts before the compositor exists cannot take them (NVIDIA's did, and offscreen Shingle died from SIGTERM without saving its session).

Every child process gets one client environment, built by `shingle_session::ClientEnvironment::new` and returned by `Compositor::client_environment`: `WAYLAND_DISPLAY` is Shingle's socket, `WAYLAND_SOCKET` is removed, `DISPLAY` is Shingle's own X display (removed when `xwayland.mode` is `false`), `WAYFIRE_SOCKET` is the IPC socket with `--ipc` and removed without it, and `_JAVA_AWT_WM_NONREPARENTING` is `1`, as Wayfire sets it. That covers `--spawn` (nested and headless), autostart, restored sessions, config command bindings, IPC binding commands (run by the frontend, or by the compositor when there is none), `stipc/run` and the lock client. Before XW-1, nested passed the host's `DISPLAY` to all of them, so X11 clients opened on the host's Xwayland, and without `--ipc` also the host's `WAYFIRE_SOCKET`. The binary no longer sets `WAYFIRE_SOCKET` in its own environment, and `Frontend::new` enables IPC before it starts any client. `cargo tree -p shingle` has no winit. Details and the reasons for the layout are in the design's [The `shingle` binary](design/native-backend.md#the-shingle-binary).

### Backend host API

What a native backend needs from `Compositor` (NB-2 in [design/native-backend.md](design/native-backend.md#nb-2-shingle-compositor-host-api-what-a-real-backend-needs-from-compositor), crates/shingle/src/lib.rs). Unit-tested; used by nested and by the native backend, which has not run on a seat yet.

- `shutdown_requested()`: SIGINT, SIGTERM and `request_quit` end the nested backend cleanly, saving the session.
- `impl AsFd`: the event-loop descriptor, readable whenever `dispatch_pending` has work, including a 50 ms timerfd tick for idle timeouts and IPC.
- `set_output_info(OutputInfo)`: connector name, make, model, serial, physical size, subpixel layout and refresh rate for `wl_output`, xdg-output, wlr-output-management, ext-workspace ids and IPC. The default is still `HEADLESS-1` at 60 Hz. There is no mode list yet, and the core output keeps its `HEADLESS-1` id (both NB-9).
- `frame_presented(PresentInfo)`: frame callbacks and `wp_presentation` feedback with the backend's timestamp, refresh interval, sequence number and flags. `frame()` reports "now" with the `OutputInfo` refresh rate.
- `set_input_time`: seat input carries the backend's `CLOCK_MONOTONIC` event time. Input and frame-callback timestamps now use `CLOCK_MONOTONIC` instead of the time since startup.
- `set_session_active(bool)`: pausing releases all held keys, buttons, touches, modifiers and gestures, then drops seat and STIPC input and withholds frame callbacks until resumed.
- `set_default_cursor(bool)`: draws the theme's default arrow when no client cursor applies. Off in nested.
- Input-device registry (NB-5): `add_input_device(InputDeviceInfo)` returns an `InputDeviceId` that every keyboard, pointer, gesture and touch entry point takes; `remove_input_device` releases what the device holds and unregisters it. Keys, buttons and touch points are held per device, so disabling one keyboard does not release keys held on another, and `Event::InputDeviceChanged` carries the ID. Nested registers its three devices as IDs 1 to 3, and its `input/*` IPC output is unchanged.

### Native backend: seat and input

NB-6 in [design/native-backend.md](design/native-backend.md#nb-6-as-built), crate `shingle-native`. Built, clippy-checked and unit-tested through fakes only; it has not run on a seat, because this host's seat belongs to the operator's session and the test machine does not exist yet. Its hardware checks are steps 1 to 8 of [native-testing.md](native-testing.md).

- `shingle` from a VT login selects native. It refuses an SSH login without `XDG_SEAT` before opening anything, then opens the seat with libseat (seatd, logind or builtin), waits up to 5 s for it to be enabled and refuses libseat's `builtin` and `noop` backends unless `--allow-builtin-seat` is given. Every refusal is "no seat: CAUSE; run from a VT login or start seatd" (or names the option) with status 1, before the Wayland socket exists or any client starts.
- libinput on libseat's devices, with udev hotplug. Each capability of a device is a seat device in `input/list-devices` with libinput's name, vendor and product; switches and tablets are ignored. Input reaches clients with libinput's timestamps. Wayfire's `[input]` device options are applied per device (acceleration profile and speed for mice and touchpads, tap to click, click and scroll method, natural scrolling, disable while typing or with a mouse, tap and drag, drag lock, left-handed mode, middle emulation), and keyboard LEDs follow the lock state.
- `input/configure-device` releases what the device holds, including its keys in the shared xkb state, and sets libinput's send-events mode once none of the libinput device's kinds is enabled.
- Ctrl+Alt+F1..F12 asks libseat to switch VT and the key is not passed on. A seat pause suspends libinput, releases everything held (keys, buttons, touches, the switcher, drags, gestures, key repeat) and acknowledges; the resume reopens the devices, which keep their IPC ids and enabled state, removes devices unplugged meanwhile and resends the LEDs.
- SIGINT, SIGTERM, the quit binding and IPC end the loop, save the session and close libinput's devices and the seat.
- Diagnostics go to standard error and `$XDG_STATE_HOME/shingle/native.log`, with panics.
- The display is NB-7's; see the next section.

Only hardware can show: whether libseat's logind and seatd backends grant, pause and resume the seat as the fakes assume (including the order of libinput's removals and releases during `libinput_suspend`), whether libseat's log line reliably names the backend, real devices' capabilities, tap finger counts and configuration support, `libinput_event_*_get_time_usec` matching the clients' times, LED updates, the send-events mode on real keyboards, touchpads with and without an external mouse, absolute and touch coordinates on real touchscreens, and tty1 being usable after SIGTERM and SIGKILL.

### Sessions

The persistent tiling model records workspace, tree order, split weights, window geometry, floating/tiled and snapped state and related flags. Sessions are written atomically: a temporary file, fsync, rename, then an fsync of the directory.

The model holds workspace sets, as Wayfire does (MO-1 in [design/multi-output.md](design/multi-output.md#mo-1-as-built)): each set has its workspaces and their trees, is shown on at most one output and keeps its home output and EDID identity while parked, and new sets take the lowest free index from 1. `Shingle::transfer_wset` moves a set's windows to another set, appended on the same workspaces, and can remember where they came from; `Shingle::return_windows` puts every window still away from a set back at its old place from the set's kept copy of its trees, leaving out windows closed or moved since; `Shingle::find_parked_wset` finds the set a returning output should show, by EDID identity, then by connector name. The compositor still uses only the output-keyed calls, so nothing parks yet; MO-2 adds the outputs that do. Sessions are written as version 2: one record per set with the output showing it, its home and identity and its kept copy, each window's away record and the active output. A version 1 file loads as one shown set per saved output.

While Shingle runs, the frontend saves after every layout change by cloning the model and handing the snapshot to `SessionWriter` (crates/shingle-session/src/writer.rs), which validates, serializes and writes it on a thread of its own, so the compositor thread never waits for the disk. A snapshot submitted while another is still waiting replaces it, so a burst of changes during one slow write costs a single write of the newest state, and since one thread takes the newest snapshot each time, an older one is never written after a newer one. A snapshot equal to the last one written successfully is skipped. A failed write is printed once per kind of error (the `io::ErrorKind`, otherwise the error variant) until a write succeeds again. There is no time-based debounce: Wayfire persists no layout session to compare with (its only delayed write-side work is the config reload, which Shingle already delays with `config_reload_delay`), and coalescing behind the write in progress already limits the writes to what the disk can take, where a timer would only delay durability. The headless backend saves only at exit, after the compositor is gone, and keeps writing synchronously.

The requirement is exact tile order and size after logout and login. Test full frontend/session cycles, not only serialization.

Views blocked before their first map (see [ipc.md](ipc.md#map-blocking)) are placeholders until released. They must not be rendered, focused, included in Scale or reported as mapped.

On shutdown (SIGINT, SIGTERM, the quit binding or IPC) every backend takes the session snapshot first, then stops Xwayland and removes the X display's lock and sockets (`Compositor::stop_xwayland`; headless drops the whole compositor), and only then writes the snapshot (`SessionStore::save_snapshot`; for the frontend `SessionWriter::finish`, which first waits for a background write in progress, drops one still waiting and then writes the final snapshot on the calling thread). The write syncs the file and its directory, which took 8 to 17 s on this host's shared `/home` while other builds were writing; before the fix the display stayed bound for that long, and a SIGKILL sent because the exit took too long left the lock and socket behind. The exit still waits for the sync, so the saved session is durable; with a write in progress it can wait for two. After `Frontend::shutdown` the frontend saves nothing more, because the model no longer holds the X windows.

A session file that is not UTF-8, not JSON or not a valid snapshot is renamed to `session.json.corrupt-SECONDS` next to it (with `.N` if that name exists; nothing is overwritten or deleted), a warning names both paths, and Shingle starts with an empty session.

### Idle and locking

`shingle-lock` is an `ext-session-lock-v1` client with swaylock-style options and PAM authentication through `shingle-auth`. Idle, DPMS, fullscreen suppression and lock coordination exist. Option compatibility does not imply full swaylock parity; keep testing real locking.

### Configuration and WCM

- YAML is native and rejects unknown fields.
- Wayfire INI and i3-style imports cover many options and key bindings, but not all of them. Since WG-1 ([design/wayfire-gaps.md](design/wayfire-gaps.md#wg-1-as-built)) `wayfire.ini` is read as wf-config reads it: every unescaped `#` starts a comment, `\#` is a literal `#` (WCM's escaped colours), a line ending in `\` continues, and names and values are trimmed as wf-config trims them. A value Shingle cannot use keeps its default and becomes a warning with its line, section and option, instead of refusing the file; so does each section of a plugin Shingle does not have, once. i3 files warn the same way; YAML stays strict. `shingle` prints the warnings once at start and on a reload, `shingle-wcm --check` prints them and exits 0, and 1 for a file it cannot read. Activators are split into their kinds: keys and buttons are bound, while a modifier alone (`<super>`), touch gestures (`pinch in 4`, which used to bind the key `4`) and hotspots warn and are never bound. `squeezimize` becomes `zoom` and `fire`, `zap` and `spin` become `fade`, with a warning. The view matcher reads Wayfire's `PREDICATE equals true|false`, so Wayfire's default `animate/enabled_for` parses. An unescaped `#` after `=` is now a comment, as in Wayfire, so a hand-written `#RRGGBBAA` colour needs its `\#`; `#RGBA` colours are read too.
- Since WG-2 ([design/wayfire-gaps.md](design/wayfire-gaps.md#wg-2-as-built)) a Wayfire import starts from Wayfire's metadata defaults, from crates/shingle-config/data/wayfire-options.tsv, which tools/wayfire_options/generate.py writes from wayfire:metadata/*.xml at the surveyed commit: an empty `wayfire.ini` has a 3×3 grid, exits on `ctrl+alt+backspace` and binds none of `super+shift+q`, `super+s`, `super+d`, `super+n` or `super+1`. Shingle's bindings without a Wayfire option (moving and resizing tiles, the ten workspace keys, reload, lock) are off unless set by their Shingle names. `[core] plugins`, or Wayfire's default list, is honoured for every plugin Shingle implements: an unlisted plugin reads none of its options and its bindings, effects, animations, rules and autostart entries are off, nothing tiles without `simple-tile`, new views open at the workarea's top left without `place`, and the globals of the protocol plugins exist only when listed; IPC stays with `--ipc`. `[vswitch] binding_N`, `with_win_N` and `send_win_N` work, and `autostart_wf_shell` starts `wf-panel` and `wf-background` unless an entry runs them. `wayfire/get-config-option` and `list-config-options` answer every option of the table: live for the 18 that `set-config-options` changes, otherwise as the file wrote it, with Wayfire's default.
- Since WG-3 ([design/wayfire-gaps.md](design/wayfire-gaps.md#wg-3-as-built)) children get `XDG_CURRENT_DESKTOP=wayfire` when Shingle has none (one the login set is kept), `XCURSOR_THEME` (unless the theme is `default`) and `XCURSOR_SIZE` from the cursor settings as they are when the child starts, and `WAYFIRE_CONFIG_FILE` with the absolute path of a Wayfire configuration file; for YAML and i3 the variable is removed, so neither a host Wayfire's file nor a YAML file is offered to WCM. data/shingle.desktop is a Wayland session file (`Exec=shingle`, `DesktopNames=Shingle;Wayfire;wlroots`), not installed by anything; the README gives the steps. Starting it from a display manager runs the native backend, which has not run on hardware.
- Since WG-4 ([design/wayfire-gaps.md](design/wayfire-gaps.md#wg-4-as-built)) a binding of modifiers alone is a binding of its own, Wayfire's `<super>` and YAML's `super`: it triggers when the modifiers are pressed and released with no other key, pointer button, scroll or touch in between and within `input.modifier_binding_timeout` (`[input] modifier_binding_timeout`, 400 ms, 0 never cancels). `keybindings.toggle_menu` (`[wayfire-shell] toggle_menu`, default `super`) and commands act on one; elsewhere a modifier alone still warns in a Wayfire file and never matches. `[wayfire-shell]` is a plugin of the list, and its section no longer warns.
- Since WG-5 ([design/wayfire-gaps.md](design/wayfire-gaps.md#wg-5-as-built)) `[vswipe]`'s twelve options are read when `[core] plugins` lists `vswipe` (YAML `vswipe:`), and touchpad swipes drag the workspace wall as Wayfire's vswipe does ([features.md](features.md#touchpad-workspace-swipes)). The WCM-style fixture's `[vswipe]` section, of a plugin its list leaves out, no longer warns.
- Since WG-6 ([design/wayfire-gaps.md](design/wayfire-gaps.md#wg-6-as-built)) `[decoration]`'s fourteen options are read when `[core] plugins` lists `decoration`, as Wayfire's default list does (YAML `decoration:`), with numbers clamped to Wayfire's bounds as wf-config clamps them, and server-side windows are framed as Wayfire frames them ([features.md](features.md#decorations)). `font` is kept but titles are drawn in Inter. The WCM-style fixture's `[decoration]` section no longer warns.
- Since WG-7 ([design/wayfire-gaps.md](design/wayfire-gaps.md#wg-7-as-built)) `[switcher]`'s `speed`, `view_thumbnail_scale` and `view_thumbnail_rotation` are read when `[core] plugins` lists `switcher` (YAML `switcher:`), and Alt+Tab shows Wayfire's thumbnails ([features.md](features.md#alttab-switcher)).
- The docs of `keybindings.workspace_move` (`super+shift+N`) said it follows the window; it sends the window and stays, as i3 does, which is kept. The docs, data/shingle.yaml, docs/features.md and WCM's label say so now.
- `wayfire/get-config-option` and `set-config-options` treated `simple-tile/inner_gap_size` as the outer gaps; they use the inner gap now (found while writing WG-1's real-run check).
- Physical-key and case-sensitive `xkb:` bindings are supported. They also fire from STIPC `feed_key`, which nested feeds through its keyboard like a host key, as Wayfire's headless STIPC keyboard does ([ipc.md](ipc.md#runtime-bindings)).
- Nested interprets keys with Shingle's own keymap (`shingle_frontend::keyboard`, NB-3), not the host's: ordinary bindings match Wayfire's `KEY_*` names from the evdev code, `xkb:` bindings match the keysym Shingle's layout produces, binding modifiers follow Shingle's keymap options, Scale's filter gets the text of Shingle's layout, and clients get depressed, latched, locked and group masks from that state, so Caps Lock and layout-switching keys now work in nested. Names that only winit used no longer match: `digit1` is `1` (so the default `super+1`..`super+0` work), `period` is `dot`, `bracketleft` is `leftbrace`, `shiftleft` is `leftshift`. Key repeat for bindings, the overviews and the switchers is the frontend's own timer (NB-4): the most recently pressed repeating key repeats at Shingle's `repeat_rate` and `repeat_delay`, the values clients get, and nested ignores the host's repeats.
- Comma-separated XKB layouts and per-layout variants become distinct XKB groups.
- WCM, built on the Gloomy UI library, edits, validates and converts configuration.
- Live IPC configuration updates are not written back to YAML.

### Several outputs

MO-2 in [design/multi-output.md](design/multi-output.md#mo-2-as-built), in `shingle` and `shingle-bin`. The compositor keeps its outputs in the order they were added (crates/shingle/src/output/registry.rs), each with its description, rectangle, scale, transform, configured position, IPC id and `wl_output` global. Positions are fixed where configured and `auto` otherwise, placed after the fixed outputs from left to right as wlroots does, and recomputed when an output comes, goes or changes size. Each output has its own xdg-output geometry and output-management head, and `wlr-randr` moves, rescales and resizes each head on its own.

- `Compositor::add_output` shows the parked workspace set of the same EDID identity or name, bringing back the windows away from it, or a new set; `remove_output` handles the output's set by `output_layout.unplug` (`move`, `park` or `return`, the default), always `move` for an IPC output, passes the active output on in add order and keeps the last output, dark, instead of removing it. A restored session's sets are parked and taken by their outputs as they are added; `restore_outputs` settles the rest.
- Frames and presentation feedback are per output: a window on another output gets its frame callback from that output's frames. Headless with `--outputs N` paces each output, and every output IPC creates, by its own timer.
- IPC: real output ids and set indices everywhere, every output and set listed, `wayfire/create-headless-output` and `destroy-headless-output`, `output-added`, `output-removed` and `output-wset-changed`, and Wayfire's payloads for `output-layout-changed` and `wset-workspace-changed` ([ipc.md](ipc.md#events)).
- Client protocols per output (MO-3, [MO-3 as built](design/multi-output.md#mo-3-as-built)): `wl_surface.enter` and `leave` follow the outputs a surface is shown on (crates/shingle/src/surface_outputs.rs), with that output's fractional and buffer scale; each surface's primary output paces its presentation feedback, FIFO barriers and commit-timing deadlines. Layer surfaces go on the output they name, else the active one, take their exclusive zones from it and are closed when it goes. Every output gets its own lock surface, and `locked` waits for all of them. Screencopy captures an output in its own logical coordinates into a buffer of its physical pixels. `wlr-randr --off` and `--on` turn outputs off and on, turned-off outputs stay listed as disabled heads, and configured outputs keep their placement across config reloads. wlr-output-power turns single outputs off, gamma ramps are per output, every output has its own ext-workspace group, foreign-toplevel handles enter their window's output, and Shingle warns when an output sits at a negative position that X clients cannot reach.
- Focus and moving windows (MO-4, [MO-4 as built](design/multi-output.md#mo-4-as-built)): the active output (crates/shingle/src/output/focus.rs) changes on a button press or touch down on another output, when a window on another output takes focus, through `oswitch` and through activators that name an output, and refocuses that output's current workspace, with `Event::OutputFocused` and `output-gain-focus`; the active output that goes is focused again if it comes back within `last_output_focus_timeout`. The pointer is pulled onto the closest output. `move_window_to_output` (crates/shingle/src/output/moving.rs) moves a window with its dialogs as Wayfire does: tiled windows join the target tree, floating ones are scaled into the new output and clamped, snapped and fullscreen ones are applied again, and the window lands on the workspace with the same offset from the current one. Its callers are `oswitch`, `configure-view` with `output_id`, `start_on_output` rules, `xdg_toplevel` and foreign-toplevel `set_fullscreen` with an output, drags onto another output in the frontend, the `wsets` bindings and `wsets/set-output-wset` and `wsets/send-view-to-wset` (crates/shingle/src/output/wsets.rs), and unplug transfers, which now also reconfigure floating windows. `vswitch/set-workspace` takes any output, `simple-tile` layouts any set, and the `oswitch` and `wsets` bindings run from the frontend and from headless STIPC keys (crates/shingle/src/output/bindings.rs). Dialogs map on their parent's output.
- Scenes per output (MO-5, [MO-5 as built](design/multi-output.md#mo-5-as-built)): `Frontend::render` draws one output (crates/shingle-frontend/src/frontend/scene.rs), from that output's surfaces in its own coordinates, scale, transform and gamma ramp, so each window is clipped to its own output and the cursor is drawn on the output under the pointer. `Host` names the output of each redraw request and pointer warp; a commit asks for frames of the outputs its surface overlaps, and presenting a frame sends that output's frame callbacks only. Zoom, workspace slides, geometry animations and Wayfire's "Workspace set N" label (`Event::WsetSelected`, `wsets.label_duration`) are per output (crates/shingle-frontend/src/frontend/outputs.rs). Scale and Expo run on the output that was active when they started and end when another becomes active. A window being dragged is drawn on every output it crosses, and with `behavior.remove_output_limits` every window is drawn on, and enters, every output it overlaps. Screencopy is answered from the captured output's own frame; outputs created over IPC get frames at 60 Hz from the frontend and are drawn only for captures. STIPC pointer input goes through the frontend, as STIPC keys do, so STIPC drags work. The offscreen backend takes `--outputs N` and draws each output into a target of its own, paced at its refresh rate (crates/shingle-bin/src/offscreen.rs).
- Windows per output in nested (MO-6, [MO-6 as built](design/multi-output.md#mo-6-as-built)): nested opens a winit window for each output (crates/shingle-nested/src/windows.rs, crates/shingle-nested/src/lib.rs), `HEADLESS-1` to `HEADLESS-N` with `--outputs N` or `WLR_WL_OUTPUTS`, all drawing with one GPU context. A window's size is its output's, its pointer and touch input is mapped to its output, a warp moves the host cursor in the window of its output, and each window presents its own output's frames. `stipc/create_wayland_output` adds an output named after the lowest free `HEADLESS-N` and asks the host for its window (`Compositor::set_host_outputs`, `Event::CreateHostOutput`, `Host::open_output`, crates/shingle/src/output/host.rs), and `stipc/destroy_wayland_output` removes one and closes its window; elsewhere both refuse with Wayfire's errors. Closing a window removes its output under `output_layout.unplug`, and closing the last one quits.
- Monitors in native (MO-7, [MO-7 as built](design/multi-output.md#mo-7-as-built)): see [Native backend: several monitors](#native-backend-several-monitors).
- Still to come: captures are drawn at the output's logical size and scaled into the client's buffer.

### Fixes from the API documentation

Fixed on the `shingle-doc-bugs` branch (2026-11-25), each with a regression test that failed before the fix:

- `Event::DpmsChanged` is emitted once per DPMS change, from `emit_idle_changes` only.
- A mapped toplevel that commits a null buffer is unmapped as xdg-shell defines it: its window leaves the layout, `WindowDestroyed` (IPC `view-unmapped`) is emitted, focus moves on, and the xdg_surface is unconfigured again. Its next initial commit gets a configure, and its next buffer maps it as a new window with a new view ID, as Wayfire's tile plugin re-attaches a remapped view.
- `touch_cancel` forgets every touch point of the client, since `wl_touch.cancel` ends the client's whole sequence.
- Scrolling reports its source: `Compositor::pointer_axis_detailed` takes a `shingle::Axis` with an `AxisSource` and per-axis stops, finger and continuous scrolls end with `wl_pointer.axis_stop`, and nested reports winit pixel deltas (touchpads) as fingers that stop when the gesture ends.
- An aspect-preserving floating resize from the left or top edge keeps the opposite edge in place at a size limit.
- `wl_surface.damage` is converted through the viewport, buffer scale and buffer transform, following wlroots' `surface_update_damage`. Measured first with a protocol test: a 90° buffer reported the surface's top-left 10×20 at buffer (0, 0, 10×20) instead of (0, 40, 20×10), and a 180° buffer at scale 2 and a viewport crop were wrong too. No renderer reads `BufferSnapshot::damage` yet, so nothing was drawn wrongly.
- A move drag to the top edge no longer switches workspace up; the top edge is the maximize slot, and only the top corners switch, diagonally, as in Wayfire's `calc_slot` and move's `update_workspace_switch_timeout`. `grid_slot` uses `<` for the top and bottom corner bands, as `calc_slot` does.
- `set_fullscreen`, `set_sticky`, `set_minimized` and `set_maximized` emit events and run window rules only when the state changes; switching to the current workspace and moving a window to its own workspace do nothing, as Wayfire's vswitch does for the current workspace.
- `Compositor::apply_config` checks the output scale and rectangle before applying anything.
- The Wayfire import names the line number of an unknown `[zoom] interpolation_method`.
- `ShingleConfig::save_yaml` syncs the directory after the rename.
- A corrupt session file (not UTF-8, not JSON or not a valid snapshot) is renamed to `session.json.corrupt-SECONDS` (never overwritten or deleted), a warning naming both paths is printed, and Shingle starts with an empty session.
- `SessionStore::restore` and `RestoreReport` are gone, and `launch_saved` takes a `&ClientEnvironment`, so no saved client can start in the host's environment.
- An empty or relative `XDG_STATE_HOME` falls back to `$HOME/.local/state`.
- An idle inhibitor turns DPMS back on and ends an idle period, like fullscreen suppression.
- `shingle-lock` installs `shingle_auth::ZeroOnFree` as its global allocator, so the password copy that nonstick hands to PAM and then drops, and the old buffers of a growing password, are zeroed before they are freed. The copy itself cannot be zeroed in `shingle-auth`, because nonstick owns and frees it.
- `InputConfig::keymap` compiles the XKB rules, model, layout, variant and options with libxkbcommon, as Wayfire does, so `xkb_rules` and `xkb_model` take effect; it now returns a `Result`.
- `ViewMatcher::matches` and `WindowRule::matches` are removed; nothing called them.

Kept: `shingle_render::preview_tiles` and `interpolate_zoom`, which the frontend's scene build uses (crates/shingle-frontend/src/frontend/scene.rs), and `ScaleTitleFilterConfig::share_filter`, which is documented as having no effect with Shingle's single output. Several Wayfire `[output:*]` sections no longer write into one `OutputConfig`: since NB-9 each is an entry of its own (`ShingleConfig::outputs`).

### Native backend: KMS display

NB-7 in [design/native-backend.md](design/native-backend.md#nb-7-as-built), in `shingle-native`. Built, clippy-checked and unit-tested through a fake card only; it has never opened a DRM device, for the same reason as NB-6. Its hardware checks are steps 9 to 15 of [native-testing.md](native-testing.md).

- Before the Wayland socket exists, the native backend opens the boot VGA card through the seat (or the one `SHINGLE_DRM_DEVICE` names, trying the next card when the seat refuses one), requires atomic modesetting, chooses the first connected output (internal panels first) with its CRTC and primary plane and passes a `TEST_ONLY` modeset, falling back from the preferred mode through every mode by area to the CRTC's current mode. Then it opens the Vulkan adapter on the card's PCI slot (any adapter if none matches). A card, atomic support, DRM master, a mode or an adapter that is missing ends the start with a message and status 1, before any client starts.
- The modeset lights that one output and turns off whatever another session left lit: other connectors, CRTCs and planes, and VRR. Clients see the connector's name, physical size, subpixel layout and refresh rate in `wl_output`.
- Copy scanout: frames are drawn offscreen, read back within 100 ms and copied into one of two XRGB8888 dumb buffers.
- Frames are paced by page flips: one commit in flight, a new frame only after the flip, and frame callbacks and `wp_presentation` feedback (`vsync`, `hw_clock`, `hw_completion`) carry the flip's time, vblank sequence and the mode's refresh.
- DPMS from wlr-output-power-management, idle timeouts and activity turns the CRTC off (`ACTIVE=0`) and on (a full modeset), after any pending flip.
- A seat pause drops the pending flip; the resume probes the card again and makes a fresh modeset, picking a new mode or output if the old one went away.
- Failures: a flip missing for 1 s is followed by a blocking modeset, and the third in a row ends Shingle with status 2 after saving the session; a hung or lost GPU is replaced with a new renderer and textures are uploaded again, and the third loss within 60 s also exits with status 2. A flip refused for lack of DRM master counts as a pause.
- No connected output at startup is not an error: clients run and nothing is drawn. A monitor plugged in later is lit at once since NB-9 (next section).
- `SHINGLE_TRACE_FLIPS=1` logs every presented flip; with the presentation probe and tools/native_test/present_check.py it checks presentation times on the test machine.

Only hardware can show: whether real drivers accept the modeset and flip property sets as the fake does (including the teardown of fbcon's state, and `VRR_ENABLED` and the cursor plane being detached), page-flip events and their timestamps, the copy path's speed (whether a frame makes one refresh at the monitor's mode), dumb buffer strides, the adapter matching by PCI slot, `wl_output` details from real connectors, DPMS on real monitors, the console after SIGTERM and SIGKILL with a display lit, and the GPU-reset recovery, which depends on the driver.

### Native backend: outputs

NB-9 in [design/native-backend.md](design/native-backend.md#nb-9-as-built), in `shingle-native`, `shingle`, `shingle-config` and `shingle-core`. The native parts are built, clippy-checked and unit-tested through the fake card and a fake hotplug monitor only; they have never received a udev event or read a real EDID. Their hardware checks are steps 16 to 22 of [native-testing.md](native-testing.md). The parts that do not need a card were checked with `wlr-randr` in headless and nested Shingle ([With real clients](#with-real-clients)).

- Configuration: `[output:NAME]` sections, i3 `output NAME` lines and YAML `outputs` entries each keep their own `OutputConfig` with `mode` (`auto`, `off`, `highres`, `highrr`, `WxH` or `WxH@R`, parsed as Wayfire's wf-config parses it, including the refresh rate) and `vrr` (applied since NB-10). `output` is the default for unnamed outputs.
- Native: a udev monitor for the card follows DRM hotplug without a VT switch. The lit output stays while connected; otherwise the next one is lit (configured names, then internal panels, then the first connected, never one set to `off`) with its configured mode, chosen as Wayfire chooses it. With every monitor unplugged, Shingle and its clients keep running with their windows in place and nothing is drawn; a returning monitor is lit again. Hotplugs wait for a pending page flip.

- wlr-output-management lists every mode; native mode changes pass a `TEST_ONLY` modeset before they are set, after any pending flip, and tests change nothing. A config reload applies changed output modes.
- Nested and headless: an explicit configured mode sizes the headless output and the nested window and sets the refresh rate clients see; a named `HEADLESS-1` entry replaces the default; custom modes from wlr-output-management resize the output; scale and transform changes keep the physical size.
- A session restored with other output names waits for those outputs: under the default `output_layout.unplug: return`, its windows join the one output and go back when an output of that name or EDID identity appears, which a native rename counts as (MO-2).

Only hardware can show: real udev hotplug events (their timing, `HOTPLUG=1` on the card, events during a VT switch), connectors' connection state and mode lists after unplugging and replugging (including monitors that keep the connector connected in standby), real EDIDs and hwdata names, drivers accepting modesets to other modes and other connectors, whether a pending flip on an unplugged connector completes or times out, monitors following `wlr-randr` mode changes, and clients (bars, `wlr-randr`, Xwayland) handling the replaced `wl_output` global.

### Native backend: several monitors

MO-7 in [design/multi-output.md](design/multi-output.md#mo-7-as-built), in `shingle-native`, `shingle` and `shingle-bin`. Built, clippy-checked and unit-tested through the fake card (now with CRTCs, primary planes and pending flips per pipe), the fake seat and the fake hotplug monitor only; it has never opened a DRM device. Its hardware checks are steps 25 to 35 of [native-testing.md](native-testing.md).

- Every connected connector that is not `off` is lit, in priority order (lit ones, those named in `outputs`, internal panels, card order), as far as CRTCs and primary planes allow: connectors are matched to CRTCs as wlroots' `match_connectors_with_crtcs` matches them, lit outputs keeping their CRTCs (crates/shingle-native/src/crtcs.rs, `Card::allocate`). Each new monitor takes the first of its modes that passes a `TEST_ONLY` modeset together with the monitors lit before it; then one blocking modeset sets them all and turns off only what none of them uses.
- Each monitor flips on its own CRTC and is paced by its own flips; flip events are routed by CRTC to `frame_presented` of their own output, so frame callbacks and presentation feedback come from the monitor a window is on, at its refresh rate. A lost flip is recovered with a modeset of that monitor alone.
- Hotplug, resume and reloaded modes keep lit monitors on their CRTCs, drop unplugged ones (turning their CRTCs off) and light new ones. The compositor's outputs follow: the first monitor renames the default output, the others are added and removed under `output_layout.unplug`, so under `return` a window goes back to its monitor when it is replugged, also on another connector by EDID identity. Connected monitors that are not lit are listed as disabled heads; the dark last output is lit again when its monitor returns. Full modesets wait for every pending flip, and no new frame starts meanwhile.
- wlr-output-management configurations are tested and carried out as a whole: mode changes of several heads and monitors turned off and on are one `TEST_ONLY` modeset and one real one, and a failed modeset restores the old configuration (`OutputRequest` now names the state of every changed head). What a configuration set holds across hotplugs and config reloads until Shingle restarts.
- wlr-output-power and idle DPMS turn each monitor's CRTC off and on by itself.
- Absolute devices map to `input_devices.NAME.output` (Wayfire's `[input-device:NAME] output`), else to the only monitor, else to the whole layout, and relative motion crosses between monitors.
- `--outputs N` lights at most N monitors.

Only hardware can show: real drivers accepting the combined modeset of two and three CRTCs and its teardown, the CRTC routing of real encoders and `possible_crtcs`, shared limits (bandwidth, clocks) failing the combined `TEST_ONLY` and the smaller mode chosen then, flip events and timestamps of several CRTCs at different refresh rates, the copy path keeping up with several monitors on one GPU, udev events when a second monitor, a dock or an MST hub comes and goes, EDID identities of real monitors moved between connectors, `wlr-randr` and `wlopm` against several real heads, a VT switch with several monitors lit, and real touchscreens and tablets mapped to an output.

### Native backend: zero-copy scanout

NB-8 in [design/native-backend.md](design/native-backend.md#nb-8-as-built) and [design/dmabuf.md](design/dmabuf.md#nb-8-as-built), in `shingle-native`. Built, clippy-checked and unit-tested through the fake card, its fake GBM and a fake renderer only; it has never allocated a GBM buffer, made a framebuffer of one or imported one into a renderer. Its hardware checks are steps 36 to 42 of [native-testing.md](native-testing.md).

- Every lit monitor starts on copy scanout. Before its next frame, once it is on, the seat is enabled and no flip of it is pending, the display tries zero-copy: the primary plane's `IN_FORMATS` for XRGB8888 ∩ the renderer's render modifiers that hold the mode (DB-1's `DmabufCaps`) ∩ single plane by GBM, three GBM buffers (`SCANOUT | RENDERING`) with one of them, a framebuffer of each with its modifier, and the renderer importing them (`DmabufUse::Render`) and clearing them to black; then a `TEST_ONLY` flip of the plane's `FB_ID` to one of them and the same flip blocking, after which the dumb buffers are freed.
- Frames of a zero-copy monitor are drawn into the buffer off screen between the foreign acquire and release barriers, the renderer waits at most 100 ms for the GPU, and the flip is presented with `vsync`, `hw_clock`, `hw_completion` and `zero_copy`.
- Whatever fails keeps copy scanout and logs `output NAME: copy scanout, because REASON` once per monitor and mode: `SHINGLE_SCANOUT=copy`, no GBM device, a renderer that cannot import DMA-BUFs or is not on the card's PCI slot, a plane without `IN_FORMATS`, no shared single-plane modifier (naming both lists), a GBM allocation, framebuffer or import that fails, or a refused test flip. A refusal for lack of DRM master is tried again later.
- A zero-copy monitor falls back to copy buffers, by the same tested blocking flip, when a renderer cannot import its buffers (as after a GPU loss onto another device) or the card refuses a flip to one of them. A GPU loss alone keeps zero-copy, since the GBM buffers belong to the card; the new renderer imports them again. A new mode (hotplug, output management, reloaded modes) is tried again with buffers of its size; a VT switch and DPMS keep the buffers.
- tools/native_test/present_check.py takes `--scanout zero-copy|copy` and counts frames presented as zero-copy.

Only hardware can show: which modifiers real planes list in `IN_FORMATS` and whether one of them is also a Vulkan render modifier there (on NVIDIA, DB-1 found only block-linear render modifiers, so it needs nvidia-drm to list one), GBM on the card allocating with that modifier and its GEM handle on a duplicated descriptor, drivers accepting framebuffers with the modifier and a flip from linear dumb buffers to a tiled GBM buffer without a modeset, the import of GBM's buffers into the renderer and a correct picture (no wrong colours, tiling garbage or tearing) with the foreign barriers, the GPU wait keeping frames within one refresh, `ZERO_COPY` in real presentation feedback, the CPU time saved against copy scanout, buffers kept across VT switches and DPMS, new buffers after mode changes and hotplug on several monitors, and recovery from a GPU reset.

### Native backend: planes, VRR, tearing and fences

NB-10 in [design/native-backend.md](design/native-backend.md#nb-10-as-built), in `shingle-native`, `shingle-frontend`, `shingle-render` and `shingle`. Built, clippy-checked and unit-tested through the fake card and a fake renderer only; it has never set a cursor plane, `VRR_ENABLED`, an async flip or a fence on a card. Its hardware checks are steps 44 to 51 of [native-testing.md](native-testing.md). Everything is per lit monitor, on copy and zero-copy scanout alike.

- Cursor plane: each CRTC's cursor plane (type cursor, ARGB8888; one that only that CRTC can use first, and a plane shared by CRTCs goes to the first output) shows the cursor from two ARGB8888 dumb buffers of the driver's cursor size, the image written into the buffer off screen when it changes. When only the cursor moved, a flip of the cursor plane alone moves it and presents nothing to clients; otherwise the change rides on the frame's flip. The first commit that shows the cursor is tested, and every modeset (start, DPMS on, resume, hotplug) shows it again; an output turned off or unplugged turns its cursor plane off.
- The frontend hands the cursor to the plane only where the plane shows the same pixels: not on a zoomed, rotated or flipped output, with inverted colours or a gamma ramp, for a cursor buffer with a viewport, a transform, another buffer scale than the output's or a DMA-BUF, or one larger than the plane. Then it draws the cursor into the frame, switching in one flip, and the log names the reason (`output CONN: the cursor is drawn, because ...`). A plane the card refuses leaves the cursor to the frame for good. Captures do not show a cursor on the plane, as in Wayfire with a hardware cursor. Cursor surfaces keep a CPU copy of their shm buffers for it.
- The drawn cursor now moves: the frontend asks for a frame of the outputs it left and entered whenever it moves or changes (before, native's default arrow stood still until something else redrew the output).
- VRR: `VRR_ENABLED` follows the output's `vrr` where the connector's `vrr_capable` is 1 and the CRTC has the property, set by every modeset; a reload or a replugged monitor that changes it makes a modeset. A VRR output's frames are presented with a refresh of 0, and its wlr-output-management heads (version 4) report adaptive sync enabled, which they used to report disabled always. The log says why a configured `vrr` stays off.
- Tearing: frames of a monitor where a visible surface asks for asynchronous presentation (`wp_tearing_control_v1`) flip with `PAGE_FLIP_ASYNC` where `DRM_CAP_ATOMIC_ASYNC_PAGE_FLIP` says the driver takes it and the flip changes only the primary plane; their feedback has no `vsync` flag. A refused async flip is made again in sync, and that monitor's flips stay in sync.
- Fences: `shingle_render::FenceExporter` exports a sync_file of a frame's submission from a Vulkan semaphore (`VK_KHR_external_semaphore_fd`, `SYNC_FD`), and zero-copy frames hand it to the primary plane as `IN_FENCE_FD` instead of waiting up to 100 ms for the GPU. Without an exporter, after the card refused a fence (waited for on the CPU and the flip made again) or when the export fails, the renderer waits as before.
- `SHINGLE_CURSOR_PLANE=0` or `WLR_NO_HARDWARE_CURSORS=1`, `SHINGLE_ASYNC_FLIPS=0` and `SHINGLE_IN_FENCE=0` force each fallback; `SHINGLE_TRACE_FLIPS=1` ends the line of an async flip with ` async` and logs `CONN: cursor plane flip` for flips of the cursor plane alone. `present_probe --tearing` asks for tearing, and tools/native_test/present_check.py takes `--tearing` and `--vrr`.

Only hardware can show: which CRTCs have cursor planes and of what size, drivers accepting the cursor plane's property set (signed positions off the edges, the full buffer size, ARGB8888 dumb buffers, the plane on and off in flips without a modeset) and cursor-only flips with an event while frames flip on other CRTCs, the pointer's look (premultiplied alpha, hotspot, no trail or flicker) and smoothness, `vrr_capable` of real monitors, a monitor reporting adaptive sync and following the frame rate, `DRM_CAP_ATOMIC_ASYNC_PAGE_FLIP` and drivers accepting async atomic flips (with `IN_FENCE_FD`, and of tiled GBM buffers), tearing a client asked for, drivers accepting `IN_FENCE_FD` from a Vulkan sync_file and waiting for it (no half-drawn frames), the timing and CPU time with fences against the wait, and a GPU hang seen through a flip that does not complete instead of the 100 ms wait.

1. Start an isolated instance with one `wev` window. The config moves the bindings used below to `ctrl+alt`, because Wayfire's defaults grab `super`+drag and `alt+escape` before they reach the nested window; pick other keys if the host still grabs these.

   ```sh
   export T=$(mktemp -d); mkdir -p $T/run $T/cfg $T/state
   chmod 700 $T/run
   cat > $T/test.yaml <<'EOF'
   pointer: {move_button: ctrl+alt+btn_left}
   keybindings:
     fast_switcher_next: ctrl+alt+j
     expo_toggle: ctrl+alt+e
     quit: ctrl+alt+shift+q
   EOF
   env XDG_RUNTIME_DIR=$T/run XDG_CONFIG_HOME=$T/cfg \
     XDG_STATE_HOME=$T/state \
     WAYLAND_DISPLAY=$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY \
     target/debug/shingle --config $T/test.yaml \
     --ipc $T/run/ipc.sock --spawn wev
   ```

2. In a second host terminal, define an IPC helper, open a second `wev` window and register a test binding on `F8`:

   ```sh
   export T=<the same directory>
   ipc() {
     python3 - "$T/run/ipc.sock" "$1" "$2" <<'PY'

   s.connect(sys.argv[1])
   body = json.dumps({'method': sys.argv[2],
                      'data': json.loads(sys.argv[3])}).encode()
   ```
